# 内存分档与 DiskANN / SymphonyQG 框架：汇报核查稿

后续方案更新：用户已确定正式低内存分支使用 PCA + 1-bit（无 residual norm、M=32），替代本文当时尚待选择的 PQ/分页回退方向。[当前正式策略](../../experiments/03_disk_system/README.md)已接入并通过小数据一致性检查；本文历史性能数字和未完成测量不因此改变。

核查日期：2026-09-21。依据仓库现有报告、验收 JSON 与关键搜索代码；本次未重跑性能实验，未修改算法。这里的“已完成”指已有实验记录，不表示本次重新验证了全部原始数据或源码。

## 可以直接汇报的结论

目前完成了内存自适应分配框架、多种剩余内存用途的消融，以及低内存路由瓶颈诊断。2 GiB 下，热点精细记录、混合缓存和动态记录缓存已有实际收益；现有导航小图收益较小。低内存下，完整路由数据分页会引入大量额外 I/O，优先保证路由常驻的方案在已测 GIST 配置中更好。538 MiB 下，128维 PCA 1-bit 排序加原960维4-bit验证，已在独立800条查询上取得 Recall 不降且 QPS 提升75.7%的结果。

任务尚未闭环：512 MiB 的 PQ 回退、4/8 GiB 完整测量，以及 DiskANN / SymphonyQG / Ours 在同一强制内存口径下的同期完整曲线仍缺证据。已有调试与小规模等价测试，不能表述为两个基线的所有实现与所有数据集均已彻底验证。

## 1. 按512 MiB、2 GiB、4 GiB、8 GiB检查

本文将用户的512、2G、4G、8G统一按二进制单位理解，正式实验应写明单位。

| 档位 | 已有证据 | 还需完成 |
|---|---|---|
| 512 MiB | 当前自动策略预检拒绝；同版本最小分页准入约521.66 MiB，完整codes常驻准入约631.14 MiB。它们是保守账本阈值，不是实际OOM边界 | 校准完整负载开销，实现/验证预算驱动的PQ路由分支；在真正512 MiB强制上限下验收。538 MiB PCA结果不可冒充512 MiB结果 |
| 2 GiB | GIST、AG News缓存方案已有800查询×40 widths结果；hot records、hybrid、hot_dynamic有两轮结果 | 同期重测基线，统一强制机制和计时，明确实际RSS与缓存有效数据量；完成跨方法比较 |
| 4 GiB | 本次检查的04报告中未找到对应完整验收曲线 | 测page、记录、图邻接常驻/部分常驻、导航小图及组合，记录新增内存的边际收益 |
| 8 GiB | 本次检查的04报告中未找到对应完整验收曲线 | 检查实际索引是否已可全部驻留；若是，标注为驻留端点，避免将CPU/内存瓶颈解释成SSD性能 |

当前自动分支实际上是“codes放不下→分页；放得下→常驻；有余量→hot_dynamic”，并不是“放不下→PQ”。已有PQ基线不等于已经接入Ours低内存回退。PQ应比较编码字节、码本、查询LUT与工作区的总成本，不能只因名称不同就假设一定更省内存。

依据：[自动策略](../../results/04_ours_memory_budget/gist_memory_auto_policy/report.md)、[同RAM实验空结果](../../results/04_ours_memory_budget/gist_same_ram/report.md)。后者当前为0/320个已接受点，不能引用为已完成的公平内存比较。

## 2. 剩余内存：已经测出了什么

### 2.1 page与小图的直接证据

以下来自同一v3_direct协议，GIST、2 GiB RLIMIT_AS、800条查询、L100；该批每策略单轮，不与后续两轮数据混算。

| 方案 | Recall@10 | QPS | 对本批基线变化 |
|---|---:|---:|---:|
| 无新增缓存 | 0.9514 | 104.20 | — |
| page缓存 | 0.9514 | 140.46 | +34.8% |
| 热点邻接表 | 0.9514 | 107.53 | +3.2% |
| 热点精细记录 | 0.9514 | 282.02 | +170.6% |
| 混合缓存 | 0.9514 | 304.51 | +192.2% |
| 导航小图 | 0.9511 | 110.84 | +6.4% |
| 全库精细记录 | 0.9514 | 444.64 | +326.7% |

这支持继续优先研究记录/page缓存。导航小图只含2048个代表点，用于选择入口；与热点邻接缓存、整图常驻是不同方案。小图改变Recall，上表为同L观测，不能称严格等Recall加速，也不能据此否定所有小图设计。

依据：[v3_direct测试文档](../../ours_memory_budget_tests.md)。根目录旧分析页仍写“等待全部完成”，与测试文档已经列出验收结果不一致；汇报应引用具体批次报告及原始数据。

### 2.2 后续两轮记录缓存结果

| 数据集 / L100 | baseline QPS | hot records | hybrid | hot_dynamic | Recall（各方案相同） |
|---|---:|---:|---:|---:|---:|
| GIST | 111.40 | 271.18 | 303.42 | 412.92 | 0.951375 |
| AG News | 188.66 | 320.48 | 288.20 | 383.32 | 0.992625 |

hot_dynamic相对复用基线分别为+270.7%、+103.2%。但对照来自不同测量时段，不能排除环境影响，不能称严格同期因果收益。GIST L300时hybrid为200.24 QPS、hot_dynamic为188.35 QPS，所以没有“动态缓存始终最好”的结论。减少读页也不保证QPS按比例提升，缓存维护、锁和调度同样有成本。

依据：[两数据集两轮结果](../../ours_hot_records_hybrid_tests.md)。

### 2.3 低内存真正的瓶颈

联合优化独立test800、L100、两轮、相同640 MiB地址空间上限：

- route常驻+8 MiB记录缓存：107.23 QPS；route分页16 MiB+96 MiB记录缓存：16.44 QPS。腾出route空间去放记录缓存，在这里明显更差。
- 分页服务共享在途上限64→256页：15.90→20.94 QPS，+31.7%，Recall均0.951375；读页几乎不变，主要改善批量服务与等待。
- 固定页槽保护10%热点：-1.1%；记录缓存8→96 MiB：+3.4%；均未证明明确收益。

依据：[联合优化报告](../../results/04_ours_memory_budget/gist_joint_optimization/report.md)，其`final_audit.json`记录passed=true、52组运行。结论范围为本次GIST L100，不代表完整曲线或所有数据集。

## 3. 增加1-bit后，原来的1-bit是否没用了

需要区分图拓扑、数据库量化码、查询量化和新增路由表示。

- 仓库当前Ours迁移契约写的是ExRaBitQ4对称距离建图。不能笼统地把整个Ours图称为“1-bit构图”。已生成的图拓扑仍然用于在线遍历。
- 原维度DB1/MSB sidecar负责廉价筛选；候选通过后才读取4-bit记录。现有原维度路径通过`paper.short_ip`和`DIST_MODE_REUSE_*`把中间计算传给后续距离内核，并非又独立算一遍所有信息。
- 如果增加的是同一表示下的精度层，合理方案是共享已有位平面与中间量；是否真能复用必须由编码布局和距离公式证明，不能自动假设。
- 已做的PCA方案使用新的低维空间，低维1-bit仅排序并取前M个邻居进入原960维4-bit验证；跨维度short_ip复用关闭，不把低维分数作为原空间hard prune下界。它复用原图与验证数据，但不宣称复用了原维度1-bit计算。

538 MiB、两轮test800的匹配validation规则确认组：原960方法为Recall 0.951375 / 24.01 QPS / 4615.21页每查询；128维、M16、width180为0.972750 / 42.17 QPS / 2819.40页每查询。QPS +75.7%，总页数-38.9%。收益同时包含低维route常驻、候选排序和12 MiB记录缓存，不能全部归因于排序。

较激进的128维/M16/width100组只有Recall 0.943375，未达0.95；其74.57 QPS不可作为达标结果。256/512维也没有稳定优于128维的证据。

依据：[PCA报告与验收](../../results/04_ours_memory_budget/gist_pca_routing/report.md)、[Ours迁移契约](../../src/graph_core/README.md)、[共享搜索实现](../../src/graph_core/src/ours_diskann.rs)。PCA验收JSON记录passed=true、33组运行。本次未完成所有磁盘分支的逐行复审。

## 4. DiskANN与SymphonyQG：调试完成到哪里

| 方法 | 已有实现/修正及证据 | 尚未解决的边界 |
|---|---|---|
| DiskANN | 原生入口调用`DiskIndexSearcher`及`SearchMode::graph()`；已有Linux读取完成队列/短读处理修复和历史回归记录 | 全width同期性能复测尚缺；不能仅由结果一致推断所有计时路径正确 |
| SymphonyQG | 磁盘适配复用QGQuery、QGScanner、SearchBuffer、ResultBuffer、HashBasedBooleanSet；fallback先复制邻居ID，避免行读取缓冲覆盖；CPU prefetch不再等价为强制磁盘读 | 已有126组合成有序top-10对照通过，仍不是GIST/AG News全量距离与扩展轨迹等价证明 |
| SymphonyQG FastScan | 当前源码将uint16累加结果用`_mm512_cvtepu16_epi32`无符号扩展，仓库有跨INT16_MAX回归测试 | 本次只静态确认代码与测试存在，未重新编译执行；不能由此认证所有维度均无溢出 |

DiskANN最关键的实测发现：历史L100为25.54 QPS，但旧二进制、原800查询、2 GiB限制且无额外预读的诊断得到112.97 QPS；结果ID、Recall、访问/距离计数与页数一致。历史低吞吐未复现。6组诊断各单次，设备状态、执行顺序和完整width上下文未受控，不能唯一归因于版本或预读。

因此目前不能拿历史DiskANN 25.54 QPS与新Ours结果拼接，宣称算法领先若干倍。正式40-width×800-query批次在报告中仍为未启动。

依据：[算法一致性审计](baseline_algorithm_audit_20260916/README.md)、[DiskANN诊断](../../results/04_ours_memory_budget/gist_diskann_protocol_audit/report.md)、[Symphony磁盘搜索](../../experiments/03_disk_system/native/symphonyqg_disk_port.cpp)、[FastScan修正](../../baselines/symphonyqg/symqglib/qg/qg_scanner.hpp)。

## 5. 下一步按什么顺序做

1. **先冻结口径与框架边界。** 建图/拓扑、routing codec、4-bit验证/residual重排、缓存/存储分层记录；原生baseline保留各自算法，共享计时、预算测量和输入协议。RLIMIT_AS是地址空间限制，RSS是驻留量；若问题是物理RAM预算，应另用一致cgroup限制并明确swap和内核记账，不能把现有RLIMIT_AS数值当成同RAM结论。
2. **512 MiB先解决可行性。** 测基础开销、峰值、必要缓冲；接入PQ routing，与原DB1分页、PCA低维routing做同预算比较。图与验证路径先固定，便于区分量化/路由影响；任何建图编码变化另列实验。拒绝档与OOM如实记录，不放宽为538 MiB后仍标512。
3. **2 GiB补同期比较。** Ours的无新增缓存、page、hot records、hybrid、hot_dynamic、小图/组合；DiskANN及SymphonyQG按各自合法缓存对象配置相同强制上限。先做小规模正确性验收，再800查询×40 widths完整曲线，比较共同Recall目标，重复并交错次序评估漂移。
4. **依次4 GiB、8 GiB。** 保留相同输入与协议，逐项记录驻留codes、factors、邻接、记录、page、元数据、线程缓冲及未使用预算；报告容量饱和后是否还有收益。小图/入口改变单独做算法消融。
5. **专门补1-bit消融与基线回归。** 比较gate启用/禁用、可复用原维度中间量/重算、低维排序/全部验证，记录剪枝率、精算数、CPU时间、I/O和Recall；Symphony补真实数据的距离/扩展轨迹，DiskANN覆盖多批读取与完整width计时。配置需在validation锁定后才测test。

上述是待执行计划；本次整理没有启动新性能队列、替换历史二进制或更改旧结果。

## 口头汇报版本

“目前已把问题拆成低内存能否运行、额外内存怎么使用、量化层之间如何复用三个部分。2 GiB下缓存消融已经完成，现阶段记录与混合缓存比已测导航小图更值得投入；低内存主要瓶颈是routing分页，优先保住routing常驻。在538 MiB上，128维1-bit导航接原维度4-bit验证，独立测试实现Recall不降、吞吐提高75.7%。DiskANN和SymphonyQG已有读取与距离内核方面的修正及等价检查，但历史DiskANN低吞吐没有复现，因此暂不做跨批次领先结论。下一步严格按512 MiB、2、4、8 GiB补齐：先落地PQ低内存分支，再做统一内存口径下的完整同期曲线，并通过消融验证1-bit是否真正减少后续计算。”
