1. 实验目标

2: p doxcnt0WzJXuQFB5E0vIbhQPSzc
本实验目标是在统一的磁盘查询环境下评估 Ours 与现有 ANN 方法的性能差异。正式主结果固定使用 32 个查询 worker；05B/05C 的 search-index DRAM budget 固定为 2 GiB，05A 的 payload-on-SSD 主结果记录同一预算，而 05A resident 仅作为不受该预算约束的纯计算参考并单独报告 resident bytes。重点比较不同方法在 Recall@10、QPS、尾延迟、索引大小、内存占用和磁盘 I/O 开销上的表现。

2. 数据集

8: p doxcnCkpr9YpxM5AVQoVSDoU0lf
实验分为 3 个 core formal 数据集和 5 个 scale extension 数据集。Core formal 是当前验收范围；extension 只有在 metric 与 ground truth 兼容、validation/test 划分非空、2 GiB resident-code 下界可行，并且 fixed candidates、SAQ 产物、baseline shared graph、Ours graph 和五系统索引全部通过 doctor 后，才能进入正式汇总。Cohere10M 当前因官方 inner-product 真值与 L2-only runner 不兼容而禁止进入 formal；MSMARCO 当前因 DB1 常驻下界超过 2 GiB 而禁止进入 05B/05C formal。

所有正式 run 的 input manifest 必须记录 N/D/source_metric/runner_metric/k、是否归一化以及输入 SHA-256。当前 suite-05 runner 使用 exact float32 squared L2：AGNews、GIST、SIFT/BIGANN 可直接使用；单位归一化的 DBpedia、Deep1B、MSMARCO 可利用 L2 与 cosine/inner product 的排序等价性；非归一化且官方真值为 inner product 的 Cohere10M 不兼容，必须先实现并验证 IP/MIPS native ports，不能通过简单归一化后沿用官方真值。

Ours ablation 含义：

43: table doxcnuAZjADGJyopGWngt8nKgNh
ablation | 含义 | 用途
full4-resident/no-gate | full 4-bit payload 常驻内存，不使用 DB1 gate | 作为无磁盘 payload 读取的上界参考
db1-resident/full4-on-ssd | DB1 gate 常驻内存，full 4-bit payload 放在 SSD | 衡量 DB1 gate 对 full payload 读取的过滤效果

44: p doxcnhSv8beIy1wZqZfM4dQrfVH
db1+coalescing+reuse 可以理解为 Ours 的完整磁盘查询优化：先用 1-bit DB1 近似距离过滤候选点，再把需要读取 full 4-bit payload 的请求合并成更少的 4 KiB page 读取；如果同一个 query 再次访问已经读取过的 page，则直接复用，避免重复 I/O。
