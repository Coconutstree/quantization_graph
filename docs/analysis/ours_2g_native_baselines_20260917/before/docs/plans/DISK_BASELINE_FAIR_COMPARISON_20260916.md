## 1. 实验目标与不可变原则

比较 Ours、DiskANN、AiSAQ、Starling 在相同数据、硬件、查询负载和搜索内存预算下的完整磁盘检索系统性能。主要问题是：在达到相同 Recall@10 时，各方法的吞吐、延迟、内存和磁盘开销如何。

**baseline 必须保留原方法，优先直接运行固定版本的官方代码。不能为了适配我们的实验框架，修改别人的算法后仍以原方法名称报告。**

具体要求：

- 保留官方建图、剪枝、候选队列、距离计算、量化训练与编码、搜索终止、重排和 I/O 调度逻辑。
- 保留方法自带的磁盘布局和内存组织：包括 Starling 的分区、页面搜索与内存导航图，以及 AiSAQ 的 PQ 存储和读取机制。
- 允许通过官方提供的参数选择配置；参数选择属于调参，必须留存命令与依据，不能以改源码替代。
- 不强制所有方法使用 Ours 的图、量化器、页布局、缓存实现或搜索宽度。共享这些内部组件的实验应另列为受控消融，不能冒充原生系统对比。
- 外层脚本负责无损格式转换、启动、资源约束、计时和结果评估。格式转换保持向量值、维度、顺序和 ID；禁止为某一个方法私自降维、截断、归一化或重新量化输入。
- 官方版本无法运行某个数据集时，记录不支持、运行失败或预算不足。不得自行修复算法或扩展存储格式后仍将结果标为原版 baseline。

### 已有兼容补丁的处理

正式主实验采用无补丁官方实现；现有兼容补丁版本仅用于诊断，暂不进入主对比。2026-09-16 的 [AiSAQ 实机环境核验](../analysis/official_disk_baselines_20260916/aisaq_unpatched_environment.md) 已定位沙箱设备可见性和主机设备读权限问题，并准备独立无补丁验证目录。

当前 AiSAQ 接入含一个设备扇区大小查询补丁：缺少 `/dev/block` 入口时，从同一设备的 sysfs 读取逻辑扇区大小。它不是搜索算法修改，但源码并非零差异，必须明确披露，不能称为“完全未修改的官方代码”。详见 [补丁](../../baselines/patches/aisaq-logical-block-size-sysfs.patch)。

正式实验应在满足官方运行要求的环境中使用无补丁版本。若当前环境只能运行兼容版本，将它单独标为诊断结果，并保留差异审计；正式主结果等待无补丁运行环境就绪。DiskANN 已有读取层修改遵循相同规则，尤其读取批次、并发和缓存行为会影响性能，不能只验证 top-k 一致就认定性能等价。

## 3. 数据与高维兼容性

数据范围为本项目的 GIST、AGNews、DBpedia 向量文件；名称指当前本地向量版本，不能用常见公开数据集的规模代替本地文件事实。每次运行记录 base、query、ground truth 的路径、SHA256、N、维度、类型、距离度量、查询数量和查询顺序。

四种方法必须使用相同原始向量、相同测试查询和同一 ground truth。验证集用于配置选择，测试集只用于最终报告；官方可选的查询频率驱动构建也只能使用训练/验证查询。

### Starling 的运行前必查项

当前固定版本的 [aux_utils.cpp](../../baselines/starling/src/aux_utils.cpp) 在磁盘布局构建中计算：

```text
max_node_len = (graph_width + 1) * 4 + dimension * sizeof(T)
nodes_per_sector = 4096 / max_node_len
```

后续逻辑使用 `nodes_per_sector` 做除法。因此，不能假定该构建路径能处理跨页节点。以 FP32、实际图宽度 64 为例：

| 本地数据维度 | 单节点记录长度 | 是否超过 4096 B |
|---|---:|---|
| GIST：960 | 4100 B | 是 |
| AGNews：1024 | 4356 B | 是 |
| DBpedia：1536 | 6404 B | 是 |

这属于源码静态检查发现的风险，不是已完成三个数据集全量运行后的结论。必须先读取实际图宽度和索引元数据，并用目标维度的小规模样本验证完整官方流程。

GIST 可核验官方较小图度数配置是否适用；AGNews、DBpedia 的 FP32 向量本身已达到或超过一页，单纯降低图度数不能解决。官方脚本虽然有 SQ 步骤，但该步骤位于初始磁盘索引构建之后，不能未经验证就声称“开启 SQ 即可解决”。需要证明固定官方版本存在完整可运行的原生路径。

若官方路径支持 SQ 或其他压缩配置，可以作为明确标注的官方配置比较，并报告相应精度与存储差异；若无可用路径，则在对应数据集标记不支持。**不得自行加跨页节点支持、改页大小、截断维度或替换量化器来补齐曲线。**

## 4. 内存公平性

不同方法把不同内容放进内存，本身并不构成不公平。公平条件是执行同一总资源约束，并完整计入每个方法实际使用的资源。

| 方法 | 主要常驻内存内容 |
|---|---|
| DiskANN | PQ 短码、码本、索引元数据、配置启用的节点缓存、查询工作区 |
| AiSAQ | 码本、入口与元数据、查询工作区、配置启用的节点/PQ 缓存；全量 PQ 短码不要求常驻 |
| Starling | 全量 PQ 短码、码本、内存导航图及其向量/边/ID、节点到块的映射、查询工作区和缓存 |
| Ours | 实际驻留的量化/图/布局元数据、缓存、全部线程工作区，按实现核算 |

预算必须包含所有线程的候选队列、visited、距离查表、对齐 I/O 缓冲、分配器开销与加载的查询数据。例如 32 个线程各有 4 MiB 缓存，容量合计就是 128 MiB，尚未包含管理开销。

现有实验使用 `RLIMIT_AS=2 GiB`，这是**整个进程的虚拟地址空间上限**，不能写成“2 GiB 物理内存/RSS 上限”。新实验第一阶段沿用该限制以建立可核查的连续性，同时报告峰值 RSS、VmPeak、swap 和限制执行证据；这条曲线应准确称为地址空间受限实验。若研究结论需要物理 DRAM 预算比较，应另建统一的物理内存约束实验并重新测量四个方法，不能混用两种限制下的点。

建索引内存与搜索内存分别报告。官方 build memory 参数不能代替搜索进程限制。主实验允许在同一总预算内选择官方驻留比例、码长和缓存容量，报告实际用量；不要求每个方法恰好用满预算，也不以给所有方法同样多的“额外缓存”代替总内存公平。

百万规模数据若每向量 PQ 为 32 B，短码仅约 30.5 MiB。这类实验可以比较当前规模下的检索性能，但不足以单独证明超大规模 PQ 驻留瓶颈或 AiSAQ 的内存扩展优势。需要时另做预算扫描或更大规模实验。

## 5. 参数与测量协议

| 项目 | 统一条件 |
|---|---|
| 设备与运行环境 | 同一目标 SSD、文件系统、CPU/NUMA 配置和构建优化等级；记录具体版本 |
| 查询工作负载 | 同一 query/order、距离度量、k=10、32 个实际查询工作线程；核查隐藏线程 |
| 内存 | 执行第 4 节同一种总预算政策，记录真实峰值与分类 |
| 质量比较 | 在共同达到的 Recall@10 区间比较 QPS、延迟和 I/O |
| 调参 | 独立验证集、预先登记的合理搜索空间与可比调参投入；保留所有尝试 |
| 运行次数 | 每配置只测一次（repeat_id=0），报告实测值，不计算跨运行中位数/IQR/CV |
| 干扰 | 同一时间只运行一个被测搜索系统，禁止后台构建/其他基准争用目标盘 |

`L_build=400` 可以保留为 Ours 和具有相应官方参数的方法的起始配置，但不能假定各方法的同名参数语义一致。搜索 L、beam、PQ 字节数、图度数、Starling 导航参数和 AiSAQ inline/rearrange 参数按官方能力在验证集选择。相同 L 的 QPS 不能替代相同 recall 的比较。若只能达到不同 recall 上限，报告实际曲线和缺失区间，不外推。

### 缓存与 I/O

主实验采用各方法的官方缓存实现并计入总预算。记录每项缓存的容量、共享/每线程范围、是否跨查询保留及预热方式。Starling 的内存导航图和全量 PQ 码属于索引结构，不能以“统一禁用缓存”为由删除。

旧实验的 `c0` 和每查询 4 MiB 缓存，不能直接等同于 AiSAQ 的每线程跨查询 LRU。不要为了套用旧标签，强制改写官方缓存生命周期。若要做无跨查询缓存的补充实验，只能使用官方可提供的配置；不支持则如实注明。

统一执行可复现的预热协议，旧设置的 100 条查询可作为起点，但还需验证对各系统是否达到稳定状态。设备控制器缓存未受控时，只能描述实际暖存储条件，不能声称冷盘。记录官方 I/O 后端、direct/buffered 模式及操作系统页缓存政策；不能为统一后端而替换官方 I/O 调度。无法建立等价存储条件的结果单列。

### 计时与指标

吞吐测量覆盖统一查询批次的真实搜索墙钟时间；不包含索引构建、加载、预热、ground truth 计算和结果文件写出。各原生程序内部计时范围须逐一核验，不能直接拼接名称相同的 QPS 列。

主报告：Recall@10–QPS 曲线、匹配 recall 下的延迟、峰值内存、磁盘索引大小和构建成本。I/O 请求数、字节数、页数与距离计算次数仅在口径一致且真实可测时报告；不能将“读取一次节点”自动换算成“一次 4 KiB I/O”。

逐查询延迟或内部计数若官方不提供，先使用不修改搜索实现的外部观测。确需插桩时，保留原版无插桩二进制作为主性能来源，插桩版本仅供诊断，并核验结果一致与开销；不能为填齐表格编造指标或改变搜索逻辑。

## 7. 执行顺序与验收

1. 冻结四方法官方来源、版本与差异清单；优先准备可运行原版程序的环境。
2. 从本地文件生成三个数据集的准确清单，核验距离度量与 ground truth。
3. 使用目标维度的小样本验证官方完整流程，重点处理 Starling 页容量限制；无官方可用路径则记录不支持。
4. 验证格式转换、ID 映射和结果合法性；与同版本官方原生 CLI 对照结果。小样本通过不代表正式规模已通过。
5. 完成外部资源限制与计时协议，确认不改变原方法；不具备可比条件的运行保持未验收。
6. 验证集调参、冻结配置，再在测试集对每个配置完成一次测量（repeat_id=0）。
7. 检查内存、缓存、后台干扰和测量完整性，最后生成四方法共同 recall 区间内的比较图表。

当前只完成 AiSAQ、Starling 的 1024 条、64 维小规模功能验证；独立 runner 尚未执行统一 2 GiB 限制，正式接口仍为 pending。不得把接入成功表述为三个目标数据集已跑通或公平性已验收。

接入细节和已有验证证据见 [OFFICIAL_DISK_BASELINES.md](OFFICIAL_DISK_BASELINES.md)。本方案明确“原算法不改”的边界，并约束后续正式实验。

## 8. 后续执行记录：Starling（2026-09-16）

用户随后要求先运行 Starling，并将文件输出到既有 `test_L_400_w_32` 目录，与同级方法结构一致。这项指令覆盖第 6 节关于另建目录的默认建议；仅新建各数据集的 `Starling-Disk/`，不覆盖其他方法文件，整体正式验收状态保持 false。

实际从三个数据集各抽取前 1024 条原始向量，使用目标原维度运行无补丁官方程序。R64 的三次建索引均以 SIGFPE 失败，日志分别确认节点长度 4100、4356、6404 B，每页节点数为 0。GIST 改用官方参数 R48 后完成建图、导航图、分区、重布局和 32 线程搜索；返回 ID 合法且不重复，返回距离与原始 FP32 向量重算一致，最大绝对误差约 5.90e-7。该检查属于小样本验证。

GIST 百万规模 R48/L_build400 全量运行已启动，使用原测试查询及已核对 SHA256 的原查询顺序，搜索宽度沿用同级命令、搜索线程 32、beam=1；搜索进程由外层执行 2 GiB RLIMIT_AS。PQ 目标为 32 B，官方预算参数换算在本次建索引日志中实际得到 31 B，应以实际索引头为准。AGNews、DBpedia 当前原生 FP32 路径保持 blocked，不生成虚假的查询或性能点；这不代表已经排除所有其他官方版本/配置。

外层导出脚本：[run_starling_existing_layout.py](../../experiments/05_disk_system_fair/run_starling_existing_layout.py)。它不修改 Starling 源码；将官方批量摘要和原生结果 ID 转为同名 result.json/queries.jsonl 等文件。逐查询时延、P50/P95/P99、内部阶段计数等官方未导出的字段为 null，P99.9 单独保存。文件结构一致不等于满足旧严格 contract：此接入保持 diagnostic、formal_ready=false、throughput_comparable=false，不能绕过验收。

实时运行状态见各 `Starling-Disk/result.json`，具体完整性和失败原因以该文件及原生日志为准。
