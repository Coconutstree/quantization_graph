## 1. 研究目标与本次纠偏

**磁盘搜索是基础；内存常驻的量化码是可选加速层；降维是候选策略，不是系统运行的前提。**

需要回答：在给定总内存预算、固定并发和目标 Recall 下，是不常驻导航码、常驻低维码，还是常驻完整 DB1 更快？剩余空间如何用于缓存？

本轮只做启动时预算选择。不增加逐查询动态维度、动态 beam、新异步 pipeline 或高级缓存替换策略。统一的有界缓存是预算公平性的基础设施；缓存策略创新另做消融。

| 项目 | 当前事实 | 在新方案中的位置 |
|---|---|---|

## 2. 三种内存情况和统一账本

定义 `B_total` 为查询进程/服务的总预算，不是单独的码数组大小：

```text
B_total >= M_runtime + M_resident_code + M_pinned_graph
           + M_dynamic_cache + M_reserve
M_reserve = 0.10 * B_total  （首版统一规则）
```

`M_runtime` 包含码本、投影、元数据、线程栈、query buffer、候选队列、visited、在途 I/O buffer、分配器等。缓存目录/哈希表/LRU 节点、查询内复用缓存必须计入相应项，不重复、不遗漏。加载过程和稳态峰值均计入，不允许先全量加载再卸载冒充低内存启动。

| 情况 | 允许的选择 | 说明 |
|---|---|---|
| 数据常驻空间为0或很小 | `disk_only`；或有益且可行的 `reduced` | 不要求整套码加载，按需从磁盘取导航码 |
| 足以放下量化码和热点图 | `full` 或 `reduced`，可固定热点图页 | 可行不等于一定最优，交给验证集比较 |
| 扣除常驻后还有富余 | 上述模式加剩余预算页缓存 | 不再用“最多10%图节点”限制主结果 |

“零内存”只作为 `M_resident_code=0、M_pinned_graph=0、M_dynamic_cache=0` 的简称，仍报告正的运行内存与总预算。若 `M_runtime+M_reserve>B_total`，报告 `BudgetInfeasible`，不承诺能运行。

### 2.1 必须修正的当前内存问题

- 当前 `workers * 8 MiB` 是估算，不能作为实际工作区上界。按 N、D、候选宽度和 I/O 深度核算并测量分配。
- 检查每查询随 N 增长的 visited。小内存模式考虑按已访问 ID 存储的精确稀疏集合；有界集合容量必须覆盖所允许工作量，超限明确失败，不以静默清空/Bloom 假阳性改变搜索结果。
- 查询内 payload 复用缓存也必须有界；页淘汰只改变读取量，不能让算法丢失候选状态或引用失效。
- 查询/GT 的评测加载内存不得免费藏在进程外：采用固定有界查询批次并说明计时范围，或统一计入进程预算。不能全量 query/GT 意外抬高低内存下界。
- 主并发固定32；预算不够则该点不可行。workers=1 是所有方法共有的独立诊断线，不与32线程吞吐混比。

## 3. 无全局常驻码如何搜索

### 3.0 简明说明：零常驻、小内存，以及是否改变搜索策略

**零常驻不是零运行内存。** 不保留全量1-bit码、图或跨查询页缓存时，仍要给query、码本、候选队列、visited和读盘缓冲分配内存。总预算低于这些必要结构的可行下界时，应拒绝启动，不能把它写成“0字节也能搜索”。

第一版按以下步骤执行，均为待实现与验证的流程：

1. **初始化入口。** 使用原有入口ID和评分方式，按需读取入口所需的记录；不要求入口附近的图常驻。
2. **扩展节点。** 从磁盘读取当前节点u的邻接表，得到尚需评估的邻居ID。
3. **按需取导航码。** 将邻居的完整DB1及必要factor定位到磁盘页，去重并按有界批次读取；有缓存则先查缓存，没有缓存直接读入临时缓冲。
4. **计算后筛选。** 用读回的DB1计算原有非对称分数，并应用原有已核验的筛选；不因为码不在内存，就把所有邻居的full4都读回来。
5. **进一步验证。** 对需要验证的候选读取full4，立即参与距离计算，然后更新原有候选池。
6. **继续与结束。** 按原有扩展和终止规则继续，使用现有重排路径返回结果。临时页在相关计算完成后可复用；预算允许时才保留为缓存。

因此，首版首先改变的是**数据获取方式**，不是另造一套搜索决策：

| 部分 | 首版处理 |
|---|---|
| 图拓扑、入口、DB1编码和因子精度 | 保持不变 |
| 非对称评分、候选筛选、候选宽度和终止规则 | 同参数对照时保持不变，先做RAM/SSD一致性验证 |
| 码的访问 | 从全量数组直接访问，改为页定位、需求读取和可选缓存 |
| 工作区 | 改为可核算、有上限的分配；不能靠静默丢候选来满足预算 |
| 磁盘完成顺序 | 读取可合并，但按原逻辑顺序消费结果，避免I/O顺序改变搜索路径 |
| 额外优化 | 内联邻居码、动态beam和新异步pipeline后置、单独验证 |

小内存时可以将同一轮邻居分批取码，必须保留原有全局候选比较语义，不能变成“每批各取前k”或提前终止。同一页在同批需求中只发一次读取；零缓存时后续轮次再次需要该页仍可能重读，应如实计入I/O，不能宣称全查询只读一次。

若额外取码I/O成为瓶颈，再按§3.3比较内联布局。若最小工作区仍放不下，先报告不可行；降低workers或候选宽度属于另一个配置，必须对所有方法统一安排，不能只给某方法暗中修改。

验收顺序是：**能不加载全量码正确搜索 → 工作区和缓存不超预算 → 测量实际Recall/QPS/I/O → 再决定是否修改布局或搜索策略。** 此流程不承诺无常驻一定更快，也不把以前“全邻居读取full4”的消融当作它的实现。

### 3.1 首版：磁盘完整 DB1，先保证同编码语义等价

先不要同时换编码、图和搜索策略。对 Ours 完整 DB1 实现两种 reader：

```text
相同完整 DB1 记录：RAM reader / SSD demand reader
搜索扩展 u → 邻接表 → 获取邻居 v 的 DB1+factor
           → 原有非对称评分/原有经核验的筛选
           → 对需要验证的 v 读取 full4 并立即计算距离
           → 按原有候选池与终止规则继续搜索、重排
```

SSD reader 对实际需要的 DB1 记录定位到页，去重、批量读取；命中缓存直接计算，未命中读取后计算。保留完整 DB1 原有 kernel 与 factor 精度，不用低维 sign 分数替代它。

这会增加导航码 I/O，但不等于必须读取每个邻居的 full4。是否值得取决于页局部性、缓存和避免的 full4 读取，必须实测。没有理论界的近似分数不写成原空间 L2 硬下界；原有筛选也不扩大其可靠性声明。

要求：同编码同参数下，RAM/SSD reader 的距离、候选集合、终止条件一致；耗时和物理 I/O 可以不同。缓存命中与淘汰不得改变结果。尚未通过 parity 前不引入新的候选筛选。

### 3.2 存储修改

保留现有图与 full4/residual 文件，只增加版本化、只读的页化 DB1 sidecar：

```text
db1_pages.bin        # 拟新增：码+全部必要 factor，保持原编码数值
db1_pages.meta.json  # 拟新增：N、D、record/page布局、映射、版本和哈希
```

上述是拟定产物名，不代表当前已有导出器。采用固定记录或有界定位结构，避免为了寻址再加载 O(N) offset 数组。4 KiB 对齐，正确处理尾页和跨页记录。采用流式导出，不覆盖已有 sidecar。

同一布局版本的所有预算复用同一 sidecar 与磁盘索引；新旧布局不要求哈希相同，但图拓扑一致并显式记录各自布局哈希。不得为每个预算偷偷重建不同图。

### 3.3 后续布局优化，不作为首版依赖

参考 AiSAQ，将部分/全部邻居导航码内联到父节点记录，以减少独立取码。它增加复制量和索引体积，可能使节点跨页，因此需独立比较 `sidecar-demand` 与 `inline` 的页数、字节数和 QPS。**纯磁盘搜索不强制 inline-32，也不默认32位够用。** [AiSAQ 官方实现](https://github.com/kioxia-jp/aisaq-diskann)

主实验禁止为缓存预热而发起无当前计算需求的搜索读取。读取 v 的码必须参与当前距离评估；读取 v 的 full4 必须参与当前距离计算。读 u 的邻接表用于当前扩展属于有效图读取。物理页附带的其他记录可保留，但不虚报为已计算候选，也不强制计算页内所有记录。

## 4. 常驻完整码和低维码

`full`：完整 DB1 及其全部因子常驻，保持原有 Ours 语义。

`reduced(d)`：离线从原向量流式生成数据集专属投影 sign 码，只改变路由表示；不替换原始向量、不重新建图、不改 full4 空间。query 保留实值投影，评分为：

```text
score = d*s_x² - 2*s_x*<q_projected, sign_code>
```

常数 query norm 仅在需要实际近似距离的阈值中恢复。禁止 query 二值化后用 Hamming 代替当前非对称距离。投影码不是原 DB1 的位前缀，二者不能共享未经验证的因子/下界。尺度在磁盘与 RAM 的精度、投影矩阵和对齐容量全部记账。

首版候选维度使用已导出且元数据匹配的 `{64,128,256,512}` 子集，必须不超过输入维度；不存在的 artifact 不临时假定可用。投影仅在 base-only 训练子集学习，不用 test GT。不同数据集分别训练，保留投影版本（旧 AGNews 与新 NNP v2 不混为同算法版本证据）。

reduced 分支可有单独的近似筛选策略，但必须标出与 full 分支的算法差异。低维硬截断可能永久丢失有用路径，最终 full4 重排不能保证恢复。原有 `keep32/ratio1` 仅作为显式消融，不写死为新默认。

## 5. 剩余预算如何用于缓存

首版主协议：共享的4 KiB需求页缓存，固定 LRU 规则；缓存图页、磁盘导航码页、full4/residual 页，key 包括文件/布局版本与页号。先不调各类型独立比例，不引入 page-search。

```text
cache_cap = B_total - M_runtime_cap - M_resident_code
            - M_pinned_graph - M_reserve
```

若为负，配置不可行。页槽数要用“页字节+管理开销”计算，不能简单把所有剩余字节除4096。对在途页、引用中页预留有界 slot；无空槽时等待或使用已计入的 I/O 临时缓冲，不能突破 cap。

`M_pinned_graph` 默认0，通过统一小网格 `{0, 0.1*剩余可分配空间}` 选择是否固定热点图页；比例在校准前声明。热点只来自固定 validation 访问轨迹，相同训练查询与规则，但不同方法不必有相同热点 ID。固定页是缓存预算的一部分，不再在动态缓存中重复占用。首版可以只实现0档，所有方法一致，不能宣称已优化热点分配。

容量不足一页则关闭缓存；可缓存数据全部容纳后允许余量闲置。不承诺内存必须填满。现有10%节点缓存限制保留为 `legacy_cache10pct` 对照，不作为新版主协议。

冷态：新进程，动态缓存为空，固定页加载成本单独报告；暖态：用统一、冻结的 validation 序列预热。零缓存诊断同时设 pinned=0。固定页/预热读取不计入查询QPS分母，但必须另报时间与 I/O，且不得使用测试查询预热。

## 6. 自动选择规则

每个数据集、预算、目标 Recall 和并发独立建立候选配置：

```text
mode ∈ {disk_only, reduced(d), full}
graph_pinning ∈ 已实现且共同声明的候选
cache_cap = 统一预算规划器的剩余容量
search_width ∈ 统一预先声明的网格
```

筛掉预算不可行、校验失败、validation Recall 未达标的配置；在余下配置中最大化 validation QPS。完全相同的 QPS 按 I/O 更少、峰值内存更小、稳定配置ID顺序打破平局。不优先最大/最小维度，不强制常驻完整码。单次性能选择有噪声，必须明确报告。

若采用相对 Recall 退化约束，预先统一固定允许值及参考配置；参考配置的更大预算运行只能用于质量校准，不能混入当前预算性能表。默认以统一绝对目标 `{0.90,0.95,0.99}` 分别报告。

失败状态分开：`BudgetInfeasible`、`RecallNotMet`、`UnsupportedMode`、`UnprofiledBudget`、`ExecutionFailed`。不把运行错误当成算法不可行，也不擅自切换到超预算配置。

冻结 profile 至少包含：dataset/split/graph/index/code/binary hash、预算、mode、dim、workers、search_width、beam、I/O depth、工作区上限、常驻与固定/动态缓存字节数、预热规则、目标Recall、validation统计、选择器版本。test 阶段不可再选参。

“自动”是离线校准后启动时选择；相同有限网格内选出的 BestFixed 就是选择器的参考，不能把对同一表取最大值描述为超过 BestFixed 的创新。

## 7. 所有方法的公平规则

### 7.1 受控机制对照

同一 Ours 图、同一布局版本、相同 full4/residual、相同查询、相同缓存实现、相同并发与 I/O 配置。固定完整 DB1 编码比较 SSD/RAM 位置；固定缓存实现比较不同常驻表示。模式不同可以有不同缓存容量，但必须遵守同一总字节预算。

Ours 已用的图为 `results/graph/{dataset}/Ours/{dataset}_Ours_R64_Lbuild400.graph.bin`，以文件元数据及 hash 核验；不擅自替换为旧文档中的共享 FP32 图。R=64、Lbuild=400 是构建参数，不等于 search_width。

### 7.2 原生系统对照

DiskANN、AiSAQ、已有03C/05C其他方法允许原生图、编码和必要搜索机制；统一数据、预算边界、并发、设备、目标Recall、调参额度和统计规则。能接入统一缓存的适配版单独命名；不能接入的原生缓存记录其政策，不能声称“相同缓存策略”。

不能通过关闭某原生方法必要的内存结构强行标成 disk_only。不支持则标 `UnsupportedMode` 或报告最小可行预算。SymQG 暂留二级原生对照，待读取使用与内存记账审核通过后再纳入；不得把只为缓存而发出的读取计作有效精算。

03C 历史曲线可以作背景，但若缓存、预算或测试划分不同，不能直接与新版并列声称公平。主性能对照以同一新版协议重跑为准。

| P5 | 可选内联布局、量化感知旋转、动态beam/额外异步等 | 独立消融，不反向归为降维收益 |

路径前缀：原生为 `experiments/05_disk_system_fair/`；投影与选择器为 `experiments/06_adaptive_disk_ann/`；低维kernel位于 `experiments/02_diskann_fair/src/ours_diskann.rs`。上表是计划，不表示新参数已经能运行。

P1重点单测：record地址映射、factor完整性、尾页/跨页、损坏与短读拒绝、RSS中无隐藏全量sidecar副本、查询预处理不偷偷加载全量码。P2重点单测：缓存元数据记账、并发在途页去重、pin容量、零容量、visited/候选上限与溢出报告。

确定性RAM/SSD parity目标为 top-k ID及逻辑访问路径一致；若存在浮点并列，预定义ID打破平局规则，距离按明确容差验证。诊断trace单独跑，禁入QPS曲线。存储位置改变增加I/O是允许的，不能要求物理读取数一致。

## 9. 数据、预算和测试顺序

### 9.1 数据集与查询独立性

先用小型合成数据完成数值/缓存/搜索测试，再用AGNews做集成smoke，GIST做困难分布检查，最后GIST/AGNews/DBpedia运行相同多预算协议。后续10M/100M仅在资产和运行条件具备后扩展；1M结果不能证明100M能力。

数据入口为 `data/{dataset}/{dataset}_{base,query}.fvecs` 与 `{dataset}_groundtruth.ivecs`，运行前检查实际维度、数量、距离与归一化契约。GIST为1M×960；其他数据以各自manifest为准，不共享投影。

历史跨数据集pilot采用前100 validation、后900 test；旧文档200/800未自动成为实际运行事实。GIST的历史1000条查询已参与测试/诊断，不再声称重新划分后就是未见测试集。

新版使用冻结且有来源记录的新holdout；若暂无未使用查询，可继续旧查询做开发回归，但标 `development_retest`，不称独立泛化验证。可从未使用的同分布query补充；若由base另划查询，需排除自匹配并重新定义GT/数据版本，不能与旧测试暗中混合。不得覆盖旧GT。训练、调参、测试ID交集自动检查。

### 9.2 预算矩阵

所有方法共同测总预算 `{256 MiB,512 MiB,1 GiB,2 GiB,4 GiB}`，不可行点保留。另设workers=1的小内存探索 `{32,64,128 MiB}`，不保证所有点可运行。根据P0测出的模式切换阈值可增补共同预算点，校准前登记。

每个总预算均允许 `disk_only` 参与竞争，不能只在最小预算运行它。另设缓存为0的机制对照，其运行内存仍计入总预算。

主吞吐workers=32；固定beam=1和现有I/O机制。初始机制检查search_width=49；正式Recall–QPS网格预设 `{16,32,49,64,96,128,192,256,400}`，均不小于K=10。400在此是额外搜索宽度点，区别于Lbuild400。

每配置**1次**测量，不默认五次，不虚构重复实验置信区间。cold和steady分别报告，各自按统一预热规则；设备上串行跑性能测试，不与构图、编码、校验大文件等I/O任务竞争。

### 9.3 硬预算与硬件

正式硬预算验证需独立授权cgroup v2，设置总上限、禁止swap并记录memory.peak/events。无法创建时只标 `accounting_rss_pilot`；不得修改SSH服务cgroup、以RLIMIT_AS冒充RSS限制，或将未OOM当成已验证硬限制。已有结果不追溯改标签。

记录CPU/NUMA、文件系统、实际块设备及存储型号、direct-I/O支持、binary hash。ROTA信息仅为线索，不单凭它断定NVMe型号；未验证设备不得声称NVMe性能。O_DIRECT之外的buffered/mmap页缓存若存在也必须纳入总预算与冷热说明。

## 10. 指标、曲线与结果目录

必须输出：

1. 每数据集、每预算的 Recall@10–QPS 曲线：disk_only/full/reduced以及冻结的自动选择结果，原生系统另面板。
2. 固定目标Recall的 QPS–budget、I/O–budget 曲线；测试未达标的点标失败，不按test重选维度/模式。
3. 峰值内存–budget及内存分解：runtime、resident code/factors、pinned graph、dynamic cache。
4. 随预算的模式/维度选择、最小可行预算、失败原因。

I/O同时报告requests、4KiB sectors、bytes、重复读取、唯一页数和各类cache hit。**物理读取总量不能用去重后的唯一页数替代**。加上full4候选数、逻辑扩展、p50/p95/p99、启动/预热耗时、sidecar大小及导出时间。

不得把full4近似精排称为FP32精确距离。Recall统一对合法GT计算。不同目标Recall分别校准并冻结；全曲线可报告预声明宽度网格，但不能借test曲线重新选部署配置。
